- Phase 3 step 13: `publishPriceVersion()` in `src/server/db/publish-price-version.ts`. Merged as pull request #18. It is the only writer of `price_versions` and `price_components`. The caller passes an observation item id plus the component rows and the dates. The item must be `ok` or `confirmed`. A normal change fills `last_seen_at` from the previous sighting, then opens a new row. A correction sets `retracted_at` and points `replaces_version_id` at the wrong row. The returned label is `announced` or `observed`. It does not read `parsed_data` or `fetch_log`, and it does not write `price_version_evidence`. Input checks run without a database. The publish transaction locks the observation item, then the offering, and holds both until it ends. Most Neon tests roll back. Two lock tests commit so a second connection can see the wait, then delete their rows.
- Phase 3 step 14: `findForbiddenPriceWrites()` in `src/server/db/price-write-guard.ts`. Merged as pull request #19. It reads source text and does not open a database. It scans `src/`, `scripts/`, and `drizzle/`, and it skips test files. A Drizzle insert, update, or delete of the price tables is a write, and so is SQL `INSERT`, `UPDATE`, or `DELETE` of those tables, including `price_version_evidence`. The only allowed production file is the publish module. A write split across lines is still caught. The reported line is where the match starts. Fail-on-purpose tests use a fake file string.
- Phase 3 step 15: `pnpm seed` runs `scripts/seed.ts`. Merged as pull request #20. The hand-checked list is Claude Fable 5.1, Claude Mythos 5.1, and the four gpt-6 Standard rows. They read `TEST_DATABASE_URL` and skip when it is missing. `pnpm seed` was run once against `DATABASE_URL` and wrote 2 labs, 6 models, and 6 price versions. A schema-only branch URL is not in `.env` yet, so those two database tests have not been run against an empty database.
